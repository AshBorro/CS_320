
## Module Eight Reflection

This course helped me better understand how to build software that is functional, secure, and meets the user's needs. I also learned that taking the time to plan, test, and validate my code makes a big difference in the overall quality of the program.

For Project One, I created unit tests for the Contact, Appointment, and Task classes using JUnit. Those tests helped me catch errors early and made sure the program worked the way it was supposed to. I also added input validation to prevent invalid data, like IDs that were too long or blank names. That showed me that security isn't just about protecting against hackers. It's also about making sure bad data can't break the program.

Understanding what the user needs is one of the most important parts of writing software. Before writing any code, I looked at the project requirements and figured out what each class was supposed to do. From there, I built the program around those requirements and wrote tests to make sure every feature worked correctly. If you don't understand what the user is asking for, it's easy to create something that works but doesn't actually solve the problem.

When I design software, I like to break everything into smaller pieces before I start coding. Working on one class at a time made the project feel much more manageable and made it easier to find and fix bugs. After finishing each class, I tested it before moving on to the next one. This approach helped me stay organized throughout the project.

Overall, this course helped me become more confident with unit testing and writing cleaner, more reliable code. I also gained a better understanding of how testing, validation, and planning all work together to create software that is dependable and meets the user's needs.
